WAYPOINT / EXTENSIONS

Plugins, hooks y webhooks

Tutorial práctico: crea una extensión, regístrala en Waypoint, conecta eventos y ejecuta una integración externa de forma segura.

Qué vas a construir Estructura Manifest Instalar Hooks Acciones Webhooks Probar Seguridad

1. Qué vas a construir

Un plugin de Waypoint tiene dos partes. El manifest declara la identidad, capacidades y dependencias. El runtime del plugin vive en tu Worker o servicio de integración y reacciona a hooks o acciones.

Importante: el CMS registra y persiste el manifest, hooks y acciones; no carga ni ejecuta JavaScript arbitrario subido desde el panel. Esa separación es intencional.

2. Estructura recomendada

Crea un repositorio independiente para la extensión. Mantén el contrato declarativo separado del código que habla con CRM, analítica o cualquier API externa.

crm-sync/
├─ waypoint.plugin.json   # contrato que se registra en el CMS
├─ src/
│  ├─ handler.ts          # lógica de integración
│  └─ webhook.ts          # validación de firma y reintentos
├─ tests/
│  └─ handler.test.ts
└─ README.md

Usa un slug estable en minúsculas con letras, números y guiones. El slug identifica la extensión y no debe cambiar entre versiones.

3. Escribe el manifest

Este es un ejemplo completo para sincronizar entradas publicadas con un CRM. Los nombres de capacidades son etiquetas explícitas; no conceden por sí solos permisos de servidor.

{
  "name": "CRM Sync",
  "slug": "crm-sync",
  "version": "1.0.0",
  "author": "Acme Team",
  "description": "Sincroniza entradas publicadas con el CRM",
  "capabilities": [
    "content.read",
    "webhook.send"
  ],
  "dependencies": [],
  "status": "Inactive"
}

En el CMS, name, slug, version y author son obligatorios. description, capabilities y dependencies documentan el alcance. Un plugin nuevo comienza inactivo para permitir una revisión.

4. Instálalo desde la UI o WebMCP

Desde la interfaz humana

Abre Plugins en el CMS y completa Install declarative plugin: Name, Slug, Version, Author y Capabilities separadas por comas. Pulsa Install plugin. El registro queda persistido y aparece en Installed manifests.

Desde un agente

Un agente puede registrar el mismo manifest mediante la herramienta install_plugin:

await agent.call("install_plugin", {
  name: "CRM Sync",
  slug: "crm-sync",
  version: "1.0.0",
  author: "Acme Team",
  description: "Sincroniza entradas publicadas con el CRM",
  capabilities: ["content.read", "webhook.send"],
  dependencies: [],
  status: "Inactive"
});

La respuesta devuelve status: "registered" y el plugin creado. Si el slug ya existe, tiene un formato inválido o falta una dependencia, la operación se rechaza.

5. Registra un hook

Un hook escucha un evento del CMS. Asócialo al plugin con pluginSlug y usa una prioridad solo cuando necesites ordenar consumidores.

await agent.call("register_hook", {
  name: "crm_sync_after_publish",
  event: "entry.published",
  priority: 20,
  enabled: true,
  pluginSlug: "crm-sync",
  description: "Envía al CRM cada entrada publicada"
});

Para consultar el registro: list_hooks({ pluginSlug: "crm-sync" }). Para desactivar temporalmente: toggleHook en la UI o actualiza el registro sin borrar su definición.

6. Registra una acción

Una acción representa una intención ejecutable. Declara un nombre estable, una etiqueta humana, una descripción y las capacidades que requiere.

await agent.call("register_action", {
  name: "sync_entry_to_crm",
  label: "Sincronizar entrada con CRM",
  description: "Envía una entrada concreta al CRM externo",
  pluginSlug: "crm-sync",
  capabilities: ["content.read", "webhook.send"]
});

Puedes probarla desde Actions → Run test. El CMS emite un evento seguro; no evalúa funciones recibidas ni ejecuta código externo dentro del navegador.

await agent.call("dispatch_action", {
  action: "sync_entry_to_crm",
  payload: { entryId: "entry_123" }
});

7. Conecta el webhook en tu Worker

La entrega HTTP real debe vivir detrás de una acción o Worker de integración. El handler recibe un evento normalizado, valida la firma y delega el trabajo pesado a una cola o proceso asíncrono.

export default {
  async fetch(request, env) {
    if (request.method !== "POST") return new Response("Method Not Allowed", { status: 405 });
    const raw = await request.text();
    const signature = request.headers.get("x-waypoint-signature");
    await verifyHmac(raw, signature, env.WAYPOINT_WEBHOOK_SECRET);
    const event = JSON.parse(raw);
    await env.SYNC_QUEUE.send({ event, receivedAt: new Date().toISOString() });
    return Response.json({ accepted: true });
  }
};

Payload recomendado:

{
  "event": "entry.published",
  "id": "evt_01J...",
  "occurredAt": "2026-08-30T12:00:00Z",
  "entry": { "id": "entry_123", "type": "case_study" }
}

Firma el cuerpo sin modificarlo, usa el identificador de evento para deduplicar y responde rápido. Reintenta errores transitorios con backoff; no reintentes respuestas 4xx sin corregir primero el payload.

8. Prueba la extensión

  1. Registra el manifest con estado Inactive.
  2. Comprueba que aparece con list_plugins y lee su contrato con get_plugin.
  3. Registra el hook y la acción con el mismo pluginSlug.
  4. Usa Test en Hooks y Run test en Actions.
  5. Verifica en tu Worker la firma, la deduplicación y el payload.
  6. Activa el plugin solo después de revisar permisos, dependencias y logs.

9. Seguridad y límites actuales

  • No guardes API keys en el manifest; usa secretos del Worker.
  • El manifest no ejecuta código ni concede permisos de servidor automáticamente.
  • Aplica mínimo privilegio: separa lectura, escritura y envío externo.
  • Registra actor, plugin, hook, acción, recurso, resultado y timestamp.
  • Desactiva antes de retirar una integración y conserva el historial.
  • La plataforma actual ofrece registro declarativo y eventos seguros; la lógica HTTP debe implementarse en tu integración Worker.
Resumen: manifest → install_plugin → register_hook/register_action → Worker de integración → webhook firmado.
